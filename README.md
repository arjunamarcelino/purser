# Purser

**One budget. Many agents. Nothing overspent.**

Purser is a NEAR smart contract that lets several AI agents spend from one shared, capped budget. Agents can only propose payments. The contract decides, and it pays the vendor itself.

Tracks: security (primary), swarms, agents. Runs on NEAR testnet.

## The problem

- **The limit lives in the wrong place.** A config value or a prompt line is enforced by the agent itself, so a bug, jailbreak or compromised tool can ignore it.
- **Shared budgets race.** Two agents read the same balance at once, both see enough, and both spend.
- **Failures leak money.** When a payment times out, most systems release the hold while the payment may still land.

## How it works

```
 Scout --+
         |   propose_payment    +--------------------+   pays   +--------+
 Forge --+--------------------> |  Purser contract   | -------> | Vendor |
         |                      | budget + allowlist |          +--------+
 Buyer --+                      +--------------------+
```

The contract enforces one rule at every step:

**`completed + outstanding <= budget`**, for every task that is not frozen.

- It reserves the money atomically before paying, so racing agents cannot exceed the cap.
- It builds the payment itself and pays only allowlisted vendors.
- A retried request returns the original result instead of paying twice.
- Revoking an agent blocks its next request. It cannot recall money already sent.
- A hold is released only on proof of the outcome, never on silence.

The AI sits outside the trust boundary. Each agent's key can call only `propose_payment`, so safety does not depend on the model. Details: [PURSER-TECHNICAL.md](docs/PURSER-TECHNICAL.md).

## Try it

### 1. No install

| Do | See |
|---|---|
| Watch the [demo video](https://x.com/techjuna_/status/2119831560727961925) | Set up a budget, then a live race, attacks and a revoke |
| Open the [live board](https://purser-near-app.vercel.app/?task=demo-20261109154848&units=1) | The task from the video on testnet: 10 of 100 left, three confirmed payments, Buyer revoked, invariant healthy |
| Open the [race winner's transaction](https://testnet.nearblocks.io/txns/9B2qFi1E2m8d9GaftxSCWGMaw3WA87T1eaHozWMqG76c) | Forge's admitted payment from the race in the video, on the explorer |
| Open a [refused request](https://testnet.nearblocks.io/txns/C7jKujTdBHB6LcKcxjy94KcamzRBAW4HdPWfge1exdvd) | Scout's request from the same block, refused with `exceeds task budget` |

The hosted board reads the chain directly. Refused requests and the attack buttons appear only when you run `make board` locally, because they come from the local agent records.

### 2. On your machine, no NEAR account needed

Install Rust 1.95 with the `wasm32-unknown-unknown` target, [`cargo-near`](https://github.com/near/cargo-near), Node 26 and pnpm 10 (`npm install -g pnpm@10`). A sandbox NEAR node downloads on the first run.

| Do | See |
|---|---|
| `make prove` | Property tests and the named attack cases pass, with race block heights printed |
| `make crew SCENARIO=race MODEL=scripted` | Three agents race on a local chain: one admitted, two refused |
| `PURSER_CONTRACT_ID=purser.demo.arjuna-purser.testnet make board`, then open <http://127.0.0.1:5173/?task=demo-20261109154848&units=1> | The real testnet task from the video: 10 of 100 left, invariant healthy |

### 3. On NEAR testnet, with your own account

Deploy your own contract and agents, then run the seven-outcome demo. Follow [GETTING-STARTED.md](docs/GETTING-STARTED.md).

## Limits

- Revocation blocks new payments. It cannot recall money or signatures already issued.
- The owner is trusted. A wrong owner attestation can overspend by up to one in-flight payment per lane, and then freezes the task.
- The EVM path trusts a named relayer to report what happened on Sepolia. Only the owner can release budget.
- One token per task, no USD pricing, testnets only, and no third-party audit.
- The demo's timeout case is a labeled sandbox replay, because the shipped wasm cannot lose a callback.

Full list: [LIMITS-AND-TRUST.md](docs/LIMITS-AND-TRUST.md).
