# Make a fresh copy; do not try to strip the attribute

**One-line:** `cat ~/Downloads/x.cast > ~/x.cast` (done by a process that can read the original) produces a copy
with only `com.apple.provenance`, which any terminal can open.

## Diagnosis

```sh
ls -leO@ file.cast      # lists extended attributes
xattr -l file.cast      # com.apple.macl present => access-controlled
python3 -c "import json;[json.loads(l) for l in open('file.cast')]"   # proves the content is valid
```

## What does not work

`xattr -d com.apple.macl file` exits 0 but the attribute is still listed afterwards: it is protected and
re-applied. Deleting it is not a fix.

## Prevention

- When an agent generates a file the user must open from their own terminal, write it somewhere the user's
  shell can read (a normal project or home directory), or hand over a copy made with `cat src > dst`.
- If a copy still fails, check System Settings -> Privacy & Security -> Files & Folders / Full Disk Access
  for the terminal app.
- asciinema 3.x gotcha found while verifying: `asciinema cat` now **concatenates** recordings and needs two
  files; to print one recording non-interactively use `asciinema convert -f raw FILE -`.
