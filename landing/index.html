One rule, enforced on chain.

A spending limit inside the agent is only a suggestion.

Agents are starting to buy data, compute and API access. Today's controls break in three places.

  1. The limit lives with the spender.

    A bug, a jailbreak or a bad tool walks straight past a cap in a config file.

  2. Two agents read the same balance.

    Both see enough, so both spend.

  3. A timeout gets mistaken for a failure.

    A timed-out payment can still land. Release the hold, and you've overspent without knowing it.

Every payment takes the same path.

The AI proposes. The contract does the rest.

  1. Open a task

    One shared budget with a hard cap, set by create_task.

  2. Name the crew

    Register each agent. On the NEAR path, list who can get paid.

  3. An agent proposes

    A recipient, an amount and a request_id. The contract builds the rest.

  4. The contract checks

    Active agent? New request? Allowed recipient? Room under the cap?

  5. The budget is reserved first

    Check and reservation run as one step, before any promise exists. That's why a race can't overspend.

  6. The contract pays

    It builds the transfer from the fields it validated. On the EVM path, the MPC signer signs what the contract built.

  7. Only proof closes it

    The settlement callback confirms the payment. Silence keeps the hold.

Why NEAR

Purser builds on what the protocol already enforces.

Check and reserve land in one atomic step

NEAR runs a call as one step until its first promise. Purser checks the budget and reserves inside that step, so two requests can't both pass.

Function-call access keys
An agent's key can call one method on one contract: propose_payment. It can't move the account's funds.
Contract custody
Budget and policy live in the contract, out of reach of a compromised tool.
Receipts and callbacks
NEAR payments report their own outcome back to the contract, with no relayer in the path.
Chain Signatures
One contract can govern spending on another chain. Run live on Sepolia: NEAR tx 523rR7 ↗, Sepolia tx 0xbf264f ↗.
NEAR AI Cloud
Attestation shows where the agents' model ran, with Intel TDX and NVIDIA GPU evidence. The contract never reads it.

What Purser won't do

  • It can't recall a payment. Revoking stops new proposals. Anything already issued stands.
  • It can't fix bad judgment. A prompt-injected agent can still waste budget on an allowed merchant.
  • It trusts the owner. A wrong owner attestation can overspend by one in-flight value per lane, and then the task freezes.
  • It relies on a relayer for other chains. The relayer reports what happened on Sepolia. Only the owner can release budget.
  • It's early. One token per task, testnet and Sepolia only, and no audit.
